# Amazon Top-K Recommendation

## 공식 대회 베이스라인

Kaggle 리더보드의 `LightGCN (Baseline)` 점수는 **Recall@20 0.04187 (4.187%)**입니다. 과제 공지에서 베이스라인 통과 배점은 40점이며, 동점 인정 여부는 확인되지 않았습니다. 통과 여부는 Kaggle 제출 점수로 확인합니다. [Kaggle 리더보드](https://www.kaggle.com/competitions/ssu-data-science-amazon-top-k-recommendation/leaderboard)

## 인기 상품 추천 검증

대회에서 받은 `train.csv`를 `data/train.csv`에 두고 저장소 루트에서 실행합니다. Python 표준 라이브러리만 사용합니다.

```bash
python3 popularity.py
```

다른 경로를 쓸 때는 `python3 popularity.py --train /path/to/train.csv --output outputs`로 실행합니다.

- 사용자-상품 쌍을 중복 제거하고, 시드 42로 사용자마다 약 10%를 검증용으로 분리합니다. 학습 기록은 사용자마다 최소 1개 남깁니다.
- 남은 기록에서 상품별 사용자 수를 세고, 각 사용자가 학습 분할에서 이미 본 상품을 제외해 상위 20개를 추천합니다. 동률은 상품 ID 오름차순으로 처리합니다.
- 공식 Recall@20 집계 방식으로 1,371 ÷ 59,036 = **0.023223**을 재현했습니다. 학습 기록은 556,847건, 숨긴 기록은 59,095건입니다.
- `outputs/`에 `validation_train.csv`, `validation_truth.csv`, `validation_recommendations.csv`가 생성됩니다. 추천 파일은 로컬 검증용입니다.

## 아이템 협업 필터링 개선 실험

동일한 검증 분할에서 상품별 이웃 수 제한과 공동 리뷰 수에 따른 유사도 감쇠를 비교했습니다. 감쇠는 기존 코사인 유사도에 `n / (n + 5)`를 곱하는 방식이며, `n`은 두 상품을 모두 리뷰한 사용자 수입니다. 이웃 제한을 적용할 때는 조정된 유사도 순으로 상품별 상위 이웃만 남깁니다.

| 상품별 이웃 수 | 감쇠 상수 | 공통 검증 적중 수 | 공통 검증 Recall@20 |
|---|---:|---:|---:|
| 전체 | 0 | 1,953 | 0.033082 |
| 100 | 0 | 947 | 0.016041 |
| 300 | 0 | 1,146 | 0.019412 |
| 전체 | 5 | 2,726 | **0.046175** |
| 100 | 5 | 2,494 | 0.042245 |
| 300 | 5 | 2,611 | 0.044227 |

감쇠만 적용했을 때 기존 모델보다 773개를 더 맞혔습니다. 테스트한 이웃 수 제한은 같은 감쇠 설정에서 성능을 낮췄습니다.

## EASE 실험

[EASE 논문](https://arxiv.org/abs/1905.03375)의 선형 모델을 이진 사용자–상품 행렬에 적용했습니다. 정규화한 상품–상품 행렬의 역행렬을 구해 가중치를 계산하고, 사용자가 이미 본 상품은 추천에서 제외했습니다. 모든 설정은 시드 42의 공통 검증 분할에서 비교했습니다.

| 모델 | 정규화 λ | 검증 적중 수 | 공통 검증 Recall@20 |
|---|---:|---:|---:|
| 아이템 CF 감쇠 | — | 2,726 | 0.046175 |
| EASE | 50 | 2,469 | 0.041822 |
| EASE | 200 | 2,766 | 0.046853 |
| EASE | 500 | 2,839 | **0.048089** |

검증에서 최고였던 λ=500으로 전체 학습 데이터에 다시 적합해 제출용 CSV를 생성했습니다. 이 실험은 NumPy와 SciPy를 사용하며, 상품 수에 비례해 제곱 크기의 밀집 행렬을 할당합니다.

```bash
python3 popularity.py
OPENBLAS_NUM_THREADS=2 python3 ease.py
```

EASE λ=500의 Kaggle Recall@20은 **0.05072**로 공식 LightGCN 기준 0.04187을 넘었습니다. [EASE Kaggle 제출용 CSV](ease_submission.csv)

## 저장 순서 특징 실험

EASE(λ=500) 점수와 파일에서 먼저 등장한 위치가 가까운 사용자들의 상품 점수를 결합합니다. 거리의 제곱근에 반비례해 이웃 사용자에 가중치를 주고, 상품 빈도의 제곱근으로 점수를 나눕니다. 검증용으로 가린 상호작용은 사용자 첫 등장 위치 계산과 이웃의 추천 후보 집계에서 제외했습니다. 실제 파일 순서와 시드 42로 무작위화한 사용자 순서를 같은 설정으로 비교합니다.

```bash
python3 popularity.py
OPENBLAS_NUM_THREADS=2 python3 ordering.py --review-order data/train_reviews.jsonl --validation-only
```

`--review-order`를 생략하면 `train.csv`의 행을 순서의 출처로 사용합니다. `train_reviews.jsonl.gz`도 읽을 수 있습니다.

이번 실행은 사용자 ID 오름차순으로 정렬된 `train.csv`를 사용했습니다. 공지에서 언급한 `train_reviews.jsonl`의 실제 순서는 이 실험에서 확인하지 못했습니다. 각 이웃 범위는 앞뒤 사용자 수이며, 혼합 비중은 사용자별로 최대값을 1로 맞춘 두 점수 중 순서 점수에 부여한 가중치입니다.

| 10 | 0.25 | 0.038011 | 0.038231 |

| 10 | 0.75 | 0.000881 | 0.000711 |
| 10 | 1 | 0.000728 | 0.000610 |
| 30 | 0.25 | 0.038485 | 0.038536 |
| 30 | 0.5 | 0.015702 | 0.015719 |
| 30 | 0.75 | 0.001118 | 0.000949 |
| 30 | 1 | 0.000779 | 0.000678 |
| 100 | 0.25 | 0.038908 | 0.039044 |
| 100 | 0.5 | 0.016414 | 0.016024 |

CSV 순서를 섞은 후보 중 최고점은 0.038908로 EASE 단독보다 낮았습니다. 기존 EASE 제출본을 유지합니다.

## EASE와 감쇠 협업 필터링 결합

공통 검증셋에서 EASE(λ=500)와 감쇠 CF(상수 5, 이웃 제한 없음)가 찾은 정답을 사용자–상품 쌍 단위로 비교했습니다.

| 모델별 후보 수 | EASE만 적중 | 감쇠 CF만 적중 | 두 모델 모두 적중 | 합집합 적중 |
|---:|---:|---:|---:|---:|
| 20 | 656 | 543 | 2,183 | 3,382 |
| 100 | 1,409 | 985 | 5,050 | 7,444 |

상위 100개씩 합친 후보가 전체 검증 정답 59,095개 중 7,444개(12.60%)를 포함했습니다. 최종 순위에는 가중 역순위 결합을 사용했습니다. 각 모델의 상위 100개 안에 있는 상품에 `1 / (20 + 순위)`를 부여하고, 두 점수를 가중 합산해 상위 20개를 골랐습니다.

| 감쇠 CF 비중 | 공통 검증 Recall@20 |
|---:|---:|
| 0% (EASE 단독) | 0.048089 |
| 10% | 0.048699 |
| 25% | 0.050105 |
| 50% | **0.050478** |
| 75% | 0.048360 |
| 90% | 0.047158 |

50% 설정은 2,980개를 맞혀 EASE보다 141개 더 맞혔습니다. 위 설정 선택과 성능 비교에는 같은 검증 분할을 사용했습니다.

## 날짜 가중치와 비대칭 상품 인기도 보정

시드 42의 공통 검증셋에서 비교했습니다. 날짜 가중치 모델은 학습 분할에서 같은 사용자가 가까운 시기에 리뷰한 상품 쌍에 더 높은 가중치를 줍니다. 사용자 기반 CF는 공동 리뷰 수를 감쇠한 사용자 코사인 유사도로 상위 100명의 이웃을 찾습니다.

| 모델 | 공통 검증 Recall@20 |
|---|---:|
| 날짜 가중치 · 7일 | 0.019717 |
| 날짜 가중치 · 30일 | 0.024748 |
| 날짜 가중치 · 90일 | 0.029609 |
| 사용자 기반 CF | 0.031540 |
| 날짜 가중치 30일 + 사용자 기반 CF | 0.038705 |
| 날짜 가중치 7·30·90일 평균 | 0.025205 |

비대칭 CF는 공동 리뷰 수 `n`에 `n / (n + 감쇠 상수)`를 곱합니다. 사용자가 본 상품의 빈도는 제곱근으로, 추천 후보 상품의 빈도는 표의 지수로 각각 보정합니다.

| 추천 후보 인기도 지수 | 감쇠 상수 | 공통 검증 Recall@20 |
|---:|---:|---:|
| 0.25 | 5 | **0.049919** |
| 0 | 5 | 0.047175 |
| 0.15 | 20 | 0.048530 |
| 0.30 | 20 | 0.049106 |
| 0.50 | 20 | 0.047056 |
| 0.15 | 100 | 0.047734 |

```bash
python3 popularity.py
OPENBLAS_NUM_THREADS=2 python3 temporal_cf.py

OPENBLAS_NUM_THREADS=2 python3 asymmetric_ensemble.py
```

비대칭 CF의 최고 설정(후보 빈도 지수 0.25, 감쇠 5)을 EASE와 역순위 결합했습니다.

| 비대칭 CF 비중 | 공통 검증 Recall@20 |
|---:|---:|
| 25% | 0.049394 |
| 50% | 0.050020 |
| 75% | 0.050054 |

기존 EASE + 감쇠 CF의 0.050478을 넘긴 설정이 없어 기존 제출 후보를 유지합니다.

## 결합 모델 오류 분석

시드 42 공통 검증셋에서 EASE와 감쇠 CF의 상위 후보를 다시 생성하고, 50:50 결합 모델의 적중 2,980개를 재현했습니다. 집계 단위는 검증 정답 사용자–상품 쌍입니다.

| 검증 정답의 위치 | 정답 수 | 결합 상위 20개에 포함 | 놓친 정답 |
|---|---:|---:|---:|
| 두 모델 모두 상위 20개 | 2,183 | 2,182 | 1 |
| EASE만 상위 20개 | 656 | 430 | 226 |
| 감쇠 CF만 상위 20개 | 543 | 315 | 228 |
| 최소 한 모델의 상위 100개에 있고 두 모델 모두 상위 20개 밖 | 4,062 | 53 | 4,009 |
| 두 모델 모두 상위 100개 밖 | 51,651 | 0 | 51,651 |

놓친 정답 56,115개 중 51,651개(92.05%)가 상위 100개 후보 합집합 밖에 있었고, 4,464개는 후보에 있었으나 최종 상위 20개에는 들지 못했습니다. 검증 정답을 미리 안다고 가정하고 후보 합집합에서 사용자당 최대 20개를 고르는 이론적 상한은 7,444 / 59,036 = 0.126093입니다.

감쇠 CF만 상위 20개에 올린 정답 중, 사용자의 학습 이력 상품과의 최대 공동 리뷰 수가 2–4인 경우 254개 중 128개를 유지했고 5 이상인 경우 287개 중 186개를 유지했습니다. 이 집계는 검증 정답에 한정되므로, 공동 리뷰가 많은 오답도 함께 비교해야 해당 특징의 재정렬 효과를 판단할 수 있습니다.

```bash
OPENBLAS_NUM_THREADS=2 python3 analyze_ensemble.py
```

## 후보 재정렬

EASE, 감쇠 아이템 CF, 상품명 유사도 및 선형 Turbo-CF의 상위 후보를 합친 뒤, 히스토그램 기반 그래디언트 부스팅으로 사용자별 최종 20개를 선택합니다. 사용한 22개 특징에는 모델 순위, 상품 인기도, 이력 길이, 제목 유사도, 공동 리뷰 수, 판매처, 세부 카테고리, 검증 학습 이력의 평점과 리뷰 시점이 포함됩니다.

| 방식 | 로컬 Recall@20 | 적중 수 |
|---|---:|---:|
| 기존 3모델 순위 결합 | 0.055544 | 823 |
| 순위·인기도·이력 길이만으로 재정렬 | 0.056624 | 839 |
| 22개 특징으로 재정렬 | 0.062563 | 927 |
| 22개 특징 재정렬 75% + 기존 순위 25% | **0.062631** | 928 |

위 결과는 같은 공통 검증 분할에서 재정렬 학습 사용자 27,032명과 평가 사용자 9,011명을 분리해 집계했습니다. 혼합 방식은 재정렬 단독보다 정답 1개를 더 맞혔으며, 별도 상호작용 분할에서는 아직 비교하지 않았습니다. 두 방식의 Kaggle 점수는 아직 없습니다.

```bash
python3 -m pip install numpy scipy scikit-learn
python3 popularity.py
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python3 wide_rerank.py
```

`data/train.csv`와 `data/item_meta.jsonl`이 필요합니다. ZIP으로 받았다면 마지막 명령에 `--meta data/item_meta.zip`을 추가합니다. 이 스크립트는 로컬 평가 결과를 출력합니다.

## 리뷰 파일 저장 순서를 활용한 재정렬

대회 제공 `train_reviews.jsonl`에서 사용자의 첫 등장 위치를 기준으로 앞뒤 30명의 학습 기록을 활용합니다. 거리가 가까운 사용자에 더 높은 가중치를 주고, 각 후보 상품의 인기도를 보정합니다. 이 점수와 순위를 기존 재정렬 특징에 추가하고, 순서 기반 상위 100개까지 후보에 포함합니다. 로컬 검증에서는 숨긴 상호작용을 순서 계산과 후보 생성에서 모두 제외했습니다.

| 방식 | 시드 42 Recall@20 | 시드 43 Recall@20 |
|---|---:|---:|
| 기존 재정렬 | 0.062631 | 0.060539 |
| 기존 후보에 순서 특징 추가 | 0.063981 | 0.063576 |
| 순서 특징과 후보를 모두 추가 | **0.072282** | **0.070257** |

두 분할 모두 재정렬 학습에 사용하지 않은 9,011명에서 평가했습니다. 이 특징의 효과는 이번 대회 파일의 저장 방식에 의존할 수 있습니다.

```bash
python3 popularity.py
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python3 order_rerank_submission.py
```

기본 입력은 `data/train.csv`, `data/test.csv`, `data/sample_submission.csv`, `data/item_meta.jsonl`, `data/train_reviews.jsonl`입니다. 재정렬 학습에는 시드 42 검증 분할의 후보와 정답을 사용하며, 제출 후보는 전체 학습 데이터에서 다시 계산합니다. [Kaggle 제출용 CSV](order_rerank_submission.csv)
